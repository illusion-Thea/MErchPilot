# 品策智选 MerchPilot

MerchPilot 是一个面向商品经理、采购、供应链和财务人员的企业级商品规划与智能选品平台。
系统使用 Multi-Agent Mesh 协作完成市场研究、竞品分析、用户洞察、商品概念、供应商评估、
财务测算、机会评分和线上审批。

> AI 大模型应用开发面试学习只使用一个入口：[`docs/merchpilot-8-day-ai-interview-course.html`](docs/merchpilot-8-day-ai-interview-course.html)。第一次打开时不需要先理解整张路线，只点击左侧“开始：……”或驾驶舱“开始当前一步”。Day 1 会先展示商品经理的真实场景，再依次解锁“企业系统定位、六个白话概念、四层概念判断、第一段项目回答和脱稿口述”；Day 2–8 也会按“具体场景 → 三个最小概念 → 第一段答案 → 脱稿口述”逐步解锁。同一时间只显示当前任务，不要求学习者自己安排顺序；驾驶舱的“做到这里就可以停”显示的是当前小步骤验收标准，而不是整天的大目标。完成起手课后再学习完整概念、真实源码、案例、自测和每日口述。进入代码区后，先点击“进入 Day X 源码实验室”，按“业务问题 → 状态变化 → 代码边界 → 面试表达”阅读，不要直接从源码第一行硬读。课件按“两天业务、三天流程、三天重难点”组织，Day 2、Day 5、Day 8 还会分别进行业务、流程、重难点阶段综合验收；阶段关卡通过前不能误标当天完成。课件已经内置动态下一步、八天起手课、完整路线、四层概念桥、九阶段业务主线、业务闭环复述、项目术语急救箱、知识依赖地图、困惑诊断、动态面试就绪度、每日学习契约、业务与代码讲解、18 个真实源码精读单元、交互案例、自测、复习、笔记、口述录音、压力题和最终验收，不需要依赖聊天记录或其他学习文档。

逐节点学习可查看 [`docs/agent-node-topologies.md`](docs/agent-node-topologies.md)，其中包含 13 个规划节点和 1 个多模态导入节点的独立流程拓扑。

课件包含纯本地口述录音与回放。为获得麦克风权限，请只发布 `docs` 目录：`cd docs && python3 -m http.server 4173 --bind 127.0.0.1`，然后访问 `http://127.0.0.1:4173/merchpilot-8-day-ai-interview-course.html`。不要从项目根目录启动静态服务器，避免把 `.env` 等配置文件暴露为本地 HTTP 资源；录音保存在浏览器 IndexedDB，不上传后端。

修改课件后可执行 `make courseware`，自动检查八天阶段比例、每日学习内容、源码路径、18 个源码精读单元、1/3/7 天复习、题库和最终五关口述验收。

## 当前阶段

当前已完成本地企业级业务闭环，可用于本地验收、演示和后续企业适配：

- React、Redux Toolkit、Axios、Ant Design 和 AntV X6 工作台
- FastAPI 项目与审批 API
- LangGraph Multi-Agent Mesh 初始工作流
- Celery + Redis 异步任务
- Redis Checkpoint 与 WebSocket 事件流
- PostgreSQL 业务模型和 Alembic 迁移
- Excel / CSV 在线导入、列名归一化和数据质量校验
- PDF、PPTX、DOCX 和图片导入：Qwen-VL OCR/多模态抽取、表格/图表识别、片段定位和人工复核标记
- PostgreSQL 证据台账、导入任务状态与来源追踪
- BGE-M3 向量化、Milvus 索引和 BGE Reranker 重排
- Market、Competitor、User Insight 确定性检索工具与降级策略
- 可创建规划项目、启动 Agent、查询运行快照并通过 WebSocket 展示节点进度
- 规划工作台提供 Agent 执行明细和最近事件面板，刷新后仍可查看节点状态、重试次数、复用结果和错误原因
- 规划结果、线上审批和正式选品详情共用服务端证据分页，按运行时引用顺序每页加载 8 条，并持续提示已撤回但仍由运行快照保留的历史证据
- 运行事件历史通过租户隔离的 REST 接口从 Redis Stream 恢复，WebSocket 只负责增量推送
- 系统内线上审批中心，支持通过、驳回、要求修订和证据详情查看
- 首页提供本地一键演示工作区：管理员可幂等生成 15 条真实证据和待规划审批、选品验证中、待上市评审、已上市复盘四条业务主线；业务记录写入 PostgreSQL，证据由 Celery 异步写入 Milvus，并在页面显示索引进度与失败重试入口
- 工作台按业务模块分页组织，支持 URL 直达、刷新保持、权限回退和跨模块精确定位
- 顶部提供跨模块“当前项目”操作条：用户选择一次项目后，规划、审批、正式选品、商品立项和上市评审持续保持同一项目视角；从任一业务记录进入详情也会反向更新当前项目，刷新后按租户恢复
- 当前项目筛选不仅约束分页列表，也约束审批、选品、立项和上市评审统计卡；状态筛选仍可在项目范围内切换，避免列表与汇总数字口径不一致
- 审批决定支持 `Idempotency-Key` 幂等提交，同一请求网络重试不会重复处理；审批中心可按待审批、已处理和项目筛选
- 财务规则引擎，支持售价区间、单位成本、物流/平台/税费/营销费率、固定投入、销量预测、毛利率和盈亏平衡测算
- 供应商规则评估，支持供应商、MOQ、交期、可接受交期和供应风险识别
- 规划指标聚合服务会按租户、品类和市场汇总已导入的竞品、评论、趋势、成本和供应商数据，并为财务/供应商 Agent 提供证据来源的补全与候选推荐
- Concept Agent 基于竞品、用户洞察和结构化指标生成 3 个候选商品方案，分别输出定位、目标用户、证据特征、待解决痛点、功能假设、价格/成本参考、差异化假设和验证风险
- 每个候选方案输出独立方案评分：证据适配 40 分、商业可行性 35 分、数据准备度 25 分，并给出优先验证推荐和可解释评分依据
- 线上审批可确认候选商品方案；后端按候选 ID 校验并保存标准化候选快照，结果页、审批记录和 XLSX 报告均可追溯已选方案
- 审批通过后自动生成正式选品台账，沉淀候选、财务、供应、验证和完整运行快照；验证清单更新后自动同步“验证中/可立项”状态，规划人员也可维护负责人、暂缓、终止和推进备注，并在详情中查看完整时间线
- 正式选品详情的推进时间线采用服务端分页，默认每页 8 条；只加载当前页并显示完整记录总数，避免长期推进后详情弹窗一次读取全部审计记录
- 验证通过的正式选品可在系统内发起商品立项，维护负责人、目标上市日期、预算，以及立项确认、样品定版、成本定版、小批量试销和上市准备评审五阶段里程碑；里程碑必须按顺序完成，全部完成后才能确认上市
- 商品立项支持录入分渠道试销经营数据，自动汇总访客、订单、销量、收入、退款、商品成本、营销投入、转化率、退货率、实际毛利率、客单价和营销回报，并与规划毛利率进行差异对比；系统自动输出“建议推进、建议复核、暂缓推进、数据不足”评估，阻断风险未解除时不能完成试销或上市评审
- 试销详情支持按周期查看收入与实际利润趋势、按渠道比较经营表现，并允许规划人员修订已录入数据；每次修订保存修改前后快照、修改字段和操作人，进入商品立项时间线与审计台账
- 商品立项详情中的上市评审、试销经营记录和推进时间线均采用独立服务端分页；翻页只刷新当前记录区，新增或审批后自动回到首屏显示最新结果
- 规划工作台的 XLSX 报告历史采用服务端分页，默认每页 5 份；切换运行版本自动回到第一页，异步生成状态只轮询当前页记录
- 新建立项弹窗按需远程搜索可立项商品，立项列表轮询不再携带选品全量查询；试销汇总由 PostgreSQL 聚合，趋势最多展示最近 24 个周期和收入最高的 20 个渠道，并显示完整维度总数
- 同一商品立项在同一试销周期和渠道只允许一条经营记录，重复录入会提示使用修订功能；PostgreSQL 唯一约束为并发写入提供最终兜底
- 商品立项详情提供上市准备预检，集中检查五阶段里程碑、试销评估、负责人、目标上市日期和预算，并明确显示阻断项、待复核项和建议动作
- 商品立项支持在线编辑负责人、目标上市日期、预算和立项说明，修改后立即刷新上市准备预检，并将变更写入推进时间线和审计台账
- 上市准备评审已接入独立线上审批单：规划人员提交评审快照，审批人员可通过、退回修订或驳回；结果同步评审里程碑，评审历史、审批意见和预检快照可追溯
- 管理员运维审计支持按项目、对象类型和动作筛选，并通过服务端分页查看持续增长的操作记录
- 对象存储通过统一适配器接入，当前本地开发默认使用 Docker 文件卷，后续可切换企业 OSS 实现而不改业务流程
- 企业身份、OA 审批和监控平台保留 `IdentityProvider`、`ExternalApprovalProvider`、`TelemetryProvider` 适配边界；本地默认实现不影响后续企业系统接入
- SSO、OA 和监控 provider 配置会在 API 启动时校验，未注册的实现会明确失败，不会悄悄回退到本地实现
- 顶部待办与提醒中心汇总待处理的上市准备评审，审批人员可从提醒直接跳转到商品立项区域，无需逐个翻查立项记录
- 候选方案财务场景遵循“项目显式参数优先、候选参考值补缺”规则；审批选中后自动同步售价、成本、毛利、预计利润、机会评分和规划建议，修订版本沿用所选候选方向
- 每个候选方案生成商品落地前验证清单，拆分需求匹配、规格与样品、财务可行、供应交付四道验证门，并展示完成度、负责人、证据和下一步动作
- 结果页支持在全部候选方案之间切换验证清单，每个候选独立维护验证状态、备注和材料，候选卡可直接进入对应验证方案
- 规划人员可在结果页逐项更新验证门状态、填写验证备注；状态写回运行快照并进入审计台账，刷新页面后仍可继续跟踪
- 验证门支持上传、下载和删除样品报告、成本报价、供应商文件等材料；材料元数据随运行快照留痕，文件使用本地对象存储，后续可切换阿里云 OSS
- 审批中心打开方案预览时重新读取关联运行的最新快照，审批决定仍基于不可变审批摘要校验，确保审批人能看到最新验证状态和材料但不改变审批一致性
- 审批退回生成子版本时继承父版本的验证门状态、备注和材料；材料文件按子运行独立复制，父子版本可分别追溯
- 机会评分拆解，按证据、财务、供应和信息完整度输出 100 分制评分、阻断项和风险提示
- 规划建议 Agent：有 `DASHSCOPE_API_KEY` 时调用 Qwen 生成摘要、建议和风险；本地无 Key 时自动切换为可解释规则降级，不阻断审批流程
- 规划结果页展示本次使用的结构化数据覆盖量、供应商证据来源和财务参数来源，避免只展示不可解释的综合分
- 审批修订可在线调整财务与供应参数，修订内容会回写项目并触发新运行版本重新计算
- 审批修订会生成独立运行版本，父子版本通过 `parent_run_id`、`revision_no` 关联，输入快照、结果和审批轨迹可分别追溯
- 运行并发保护、审批状态一致性校验、失败快照保留和 Redis 事件流降级保护
- Agent 节点支持指数退避自动重试，执行状态、尝试次数和错误原因持久化到 PostgreSQL；失败任务可在原运行上恢复并复用已完成节点产物
- 项目参数可独立编辑，完成、失败或取消后的项目可调整参数并启动新一轮规划
- 项目支持归档和恢复：归档不会覆盖原业务状态或删除运行、审批、证据和报告历史；归档项目从日常工作区、待办和机会统计中隐藏，并保持只读
- 单项目运行历史可切换查看，历史结果与当前执行状态互不覆盖
- 任意两个运行版本可并排对比，展示参数变化、机会分、证据数量、毛利率、预计利润、盈亏平衡和供应风险
- PostgreSQL 统一审计台账，覆盖项目、运行、审批和数据导入关键动作
- 仪表盘最近活动读取真实审计数据，基础设施状态读取后端实时健康探测
- 顶部铃铛提供真实待办与提醒中心，按当前用户角色汇总待审批方案、失败/驳回项目、数据导入质量和基础服务异常，并可跳转到对应处理区域
- 管理员运维审计支持按规划项目、对象类型和操作动作筛选，并通过服务端分页追溯项目、Agent 运行、审批、选品、立项、导入和报告操作记录
- 机会评分图表读取每个项目最新运行的真实评分、毛利和供应风险数据
- 经营驾驶舱提供服务端分页和关键词检索的项目闭环台账，严格按同一项目串联需求、Agent、审批、选品、验证、立项、上市评审和上市结果；默认将阻断与人工待办置顶，并可切换按最近更新时间查看
- 闭环台账按当前身份显示“处理”或“查看”动作，避免 Viewer、Planner、Approver 看到无权限按钮；已生成的八个阶段节点均可点击直达对应项目、指定 Agent 运行版本、审批、选品或立项记录
- 顶部当前项目操作条展示需求、Agent、规划审批、正式选品、验证、商品立项、上市评审和上市结果八阶段进度，突出首个阻断原因，并按角色给出可处理或只读的下一步入口
- 当前项目同步写入 `?project_id=...`，与 `#module=...` 模块位置共同形成可复制、可书签和可分享的业务深链；链接项目不属于当前租户、已归档或不存在时自动清除失效上下文并恢复全局视角
- Celery 异步生成 XLSX 商品规划报告，包含方案摘要、评分拆解、约束参数、候选商品、落地验证、规划建议和证据明细
- XLSX 报告额外包含“规划建议”工作表，保留模型状态、建议动作和风险提示
- XLSX 导出对外部文本执行公式注入防护，并通过 Axios 轮询任务状态和下载文件
- REST 与 WebSocket 统一身份校验，所有项目、运行、导入、审批、分析和报告查询按租户隔离
- 基于角色的写操作权限：规划人员负责项目、运行、导入和报告，审批人员负责线上决策，管理员负责审计
- `GET /api/v1/auth/me` 向前端返回当前身份，Redux 保存身份状态并按角色隐藏或禁用无权限操作入口
- 页面模块导航按 Admin、Planner、Approver、Viewer 展示主责/协同/只读标签和推荐业务路径；工作指引可折叠并在浏览器保存偏好，本地身份切换会预览角色职责并自动进入最合适的起始模块
- BGE-M3 与 BGE Reranker 独立模型服务
- 对象存储、企业 SSO、外部 OA 和阿里云监控适配器接口
- 已增加独立 FastMCP 4.0.1 服务，工具契约版本为 `0.9.0`：10 个通用只读工具面向全部登录角色，同项目端到端闭环台账支持精确项目、分类汇总、状态筛选与排序；审批任务只读工具面向 `approver/admin`；规划角色可见“幂等创建草稿、复核确认启动 Agent、单项更新验证门禁、提交上市评审”4 个受控写入工具，审批角色可见“幂等领取任务、明确提交决定”2 个受控写入工具，管理员可见全部 17 个工具
- MCP 启动采用“创建草稿 → 人工复核 → 明确确认”两步门禁：启动必须提供最新项目配置指纹、精确确认词和幂等请求标识；项目参数变化后旧指纹失效，重复请求只返回原运行且不会重复投递 Celery
- Web 工作台“Agent 集成”模块可查看服务、协议、当前身份和角色化工具目录，复制客户端配置，并通过经营驾驶舱验证真实租户读取范围；页面明确说明 Agent 运行仍不能绕过线上审批、直接生成正式选品或修改商品立项
- Agent 全链路活动分页统一覆盖 MCP 创建项目、接管启动、审批领取、审批决定、验证门禁更新和上市评审提交，每个项目只展示一张卡片；卡片聚合原始创建人、最近启动、最近审批、验证和上市评审处理人、请求标识、任务/运行/方案/门禁/评审编号、状态和时间，规划、审批与管理员角色可查看，Viewer 保持隔离
- 正式选品台账支持规划人员一键进入对应验证运行；验证门禁由 Web 与 FastMCP 统一执行“先有可用人工材料，再标记验证通过”的业务规则。面试学习和个人主责范围见 `docs/interview-development-scope.md`

当前开发范围以本地 Docker 闭环为准：真实采集数据导入、质量治理、Milvus 检索、Embedding/Reranker、Multi-Agent 规划、规则/模型建议、线上审批、报告导出和审计全部优先完成。阿里云 OSS、企业 SSO、外部 OA、生产监控只保留适配器接口，不纳入当前本地开发验收阻塞项。

## 本地启动

### Windows 本机环境

仓库中的 `backend/.venv` 可能来自其他操作系统，不能直接在 Windows 使用。Windows 请运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1
```

该脚本会创建 `backend/.venv-windows`、安装后端开发依赖并按锁文件安装前端依赖。开发模式下本地身份必须使用 `local-profile:admin`、`local-profile:planner`、`local-profile:approver` 或 `local-profile:viewer`，任意 Bearer subject 不再自动获得角色。

1. 创建环境配置：

```bash
cp .env.example .env
```

2. 修改 `.env` 中的 `MODEL_ROOT`，指向包含 `bge-m3` 和 `bge-reranker-large` 的目录。

   Docker 构建默认使用可配置的 Python 镜像源，并将下载超时提升至 180 秒；模型镜像先从 PyTorch CPU 索引安装固定版本，避免 CPU 部署误拉取 CUDA 组件。可通过 `PIP_INDEX_URL`、`PIP_DEFAULT_TIMEOUT`、`PYTORCH_INDEX_URL` 和 `TORCH_VERSION` 调整。
   Reranker 使用 Transformers 直接加载本地 Cross-Encoder 序列分类模型，并通过 `RERANKER_BATCH_SIZE`、`RERANKER_MAX_LENGTH` 控制 CPU 内存和推理吞吐。
   本地模型服务默认通过 `MODEL_DTYPE=auto` 在 CPU 使用 BF16、在 CUDA 使用 FP16，并以 `MODEL_CPU_THREADS=2`、`EMBEDDING_INFERENCE_BATCH_SIZE=4` 和 `EMBEDDING_MAX_LENGTH=512` 限制 BGE-M3 首次加载与推理峰值；资源充足或硬件不支持时可显式改为 `float32`。
   如果原始模型只有 2GB 以上的 FP32 `pytorch_model.bin`，8GB Docker 环境可能在首次解包时出现额外内存峰值。可执行 `make prepare-low-memory-model SOURCE_MODEL=/原始模型目录 TARGET_MODEL=/输出目录` 生成不改动原模型的 BF16 safetensors 分片副本，然后把 `MODEL_ROOT` 指向包含两个副本的父目录。项目本地当前使用该方式保留真实 1024 维 BGE-M3 与真实 Reranker，而不是降级成随机或规则向量。
   模型请求使用独立的 `MODEL_SERVICE_TIMEOUT_SECONDS`，默认 120 秒，以覆盖 CPU 环境首次加载模型的冷启动时间；Milvus 检索仍使用较短的 `RETRIEVAL_TIMEOUT_SECONDS`。

3. 启动本地 Docker 应用（默认包含 Embedding 和 Reranker 模型服务）：

```bash
docker compose up --build
```

开发热更新模式：

```bash
make dev
```

生产部署前必须显式配置 `APP_ENV=production` 和企业 SSO 对应的 `AUTH_MODE`；生产模式会拒绝 `AUTH_MODE=local`，不会使用默认本地管理员身份。当前 `AUTH_MODE=local` 仅用于本地开发和 Docker 验收。

启动后：

- Web 工作台：`http://localhost:3001`
- API 文档：`http://localhost:8000/docs`
- API 健康检查：`http://localhost:8000/health/live`
- FastMCP 服务：`http://localhost:8001/mcp`
- FastMCP 健康检查：`http://localhost:8001/health`
- Embedding 服务：`http://localhost:8110/health`
- Reranker 服务：`http://localhost:8111/health`

宿主机端口均可通过 `.env` 中的 `*_HOST_PORT` 调整；容器之间仍使用固定内部端口，不影响 API、Worker 与 Milvus 的服务发现。

### 混合检索与索引升级

RAG使用三阶段检索：BGE-M3 Dense语义召回与Milvus BM25 Sparse关键词召回并行执行，Milvus `WeightedRanker` 默认按`0.65/0.35`融合候选，最后由BGE Cross-Encoder对融合结果精排。租户、品类、目标市场和证据质量过滤在两路召回中同时生效。

可通过以下环境变量调整融合策略：

```bash
MILVUS_HYBRID_SEARCH_ENABLED=true
MILVUS_DENSE_WEIGHT=0.65
MILVUS_SPARSE_WEIGHT=0.35
```

升级前的Dense集合`merchpilot_evidence_v1`不会被删除。新版本默认使用`merchpilot_evidence_hybrid_v2`；服务启动后执行以下命令，从PostgreSQL重新读取所有可用证据并写入新集合：

```bash
make rebuild-hybrid-index
```

如果Milvus BM25或混合查询临时不可用，系统会降级为Dense召回，继续执行Cross-Encoder精排，并在检索结果中返回`status=partial`和`retrieval_mode=dense_fallback`，不会静默伪装成完整混合检索。

## 数据导入

- 在 Web 工作台“企业数据导入”区域上传 `.csv`、`.xlsx`、`.xlsm`、`.pdf`、`.pptx`、`.docx` 或常见图片文件。
- 表格继续走字段归一化和质量治理；PDF 按页、PPTX 按幻灯片、DOCX 按正文/表格/嵌入图片、图片按图像片段进入 Qwen-VL 多模态抽取 Agent。
- Qwen-VL 默认使用 `LLM_MULTIMODAL_MODEL=qwen-vl-max`，Prompt 版本和文件页码/幻灯片/图片定位会写入证据元数据；抽取结果统一落入 PostgreSQL `EvidenceRecord`，再由 Celery 调用 Embedding 服务写入 Milvus。
- 未配置 `DASHSCOPE_API_KEY` 或单个片段识别失败时，不伪造 OCR 结果：PDF/PPTX/DOCX 仍保留可读取的原生文本，图片只标记为待人工复核；可通过 `MULTIMODAL_MAX_PAGES` 和 `MULTIMODAL_MAX_IMAGE_BYTES` 控制处理上限。
- 工作台可直接下载统一采集模板，下载接口为 `GET /api/v1/data-imports/template`；模板第一张工作表可直接回传系统。
- 单文件默认上限为 50 MB，可通过 `MAX_IMPORT_FILE_BYTES` 调整。
- 兼容表格接口为 `POST /api/v1/data-imports/tabular`；统一文件接口为 `POST /api/v1/data-imports/files`。
- 统一模板包含 37 个字段，覆盖商品、竞品、趋势、评论、供应商和成本费用，并提供字段字典、示例和采集规则。
- 中文业务列会归一化为统一系统字段；未预定义的中文业务字段仍会原样保留在标准化元数据中。
- 仅填写采集人或备注、没有业务字段的占位行会被自动忽略；百分比、`万/亿`、`台/月` 等常见数值文本会归一化为可计算数值，并保留原始值用于追溯。
- 少于 30 字的用户评论会保留原文，同时拼接品类、商品、渠道和标题作为检索上下文，提升短文本向量召回质量。
- 模板数据按行校验 7 个 P0 必填项、枚举、日期和内容长度，质量问题会写入证据元数据并可在工作台查看。
- 工作台提供租户级质量总览，可统计可用、阻断、待索引和索引失败记录。
- “数据治理分析”提供来源ID/日期覆盖率、数据类型/品类/市场覆盖范围，以及来源ID冲突和内容完全相同的重复候选。
- 规划人员和管理员可在线审核重复候选，选择“全部保留”“标记主记录”或“无需处理”；结果持久化到 PostgreSQL 并写入统一审计台账。检索同时命中同组候选和主记录时会抑制非主记录，主记录未命中时保留候选兜底，且不会删除证据或 Milvus 向量。
- 已完成导入批次可以按来源ID进行版本对比，区分新增、删除、内容变更和未变化记录；分析功能只读，不会自动覆盖业务数据。
- 已完成批次可下载 XLSX 数据质量报告；失败批次可重新解析，失败或待处理证据可重新提交 Milvus 索引。
- 规划人员可安全撤回已完成或失败批次，系统会同步清理 PostgreSQL 证据、Milvus 向量和原始文件，并写入审计台账。
- 导入完成后，Celery 按 `EMBEDDING_BATCH_SIZE` 分批调用 Embedding 服务并写入 Milvus；默认每批 128 条、上限 256 条，成功批次立即落库，失败批次独立标记并重试。
- 检索严格按租户、品类和目标市场过滤，并对相同内容按质量优先去重，避免重复导入占满候选结果。
- Agent 检索链在模型或 Milvus 暂不可用时会返回降级状态，不会阻断线上审批流程。
- 规划工作台和审批中心共用完整方案视图，展示机会分、财务测算、供应风险、评分拆解、Agent 状态以及逐条证据来源和相关度。
- 运行证据详情同时使用运行快照与 PostgreSQL 当前台账：正常情况下补齐来源文件、行号和质量状态，原始导入批次撤回后仍保留历史证据摘要用于审批与审计追溯。

完整 Docker 端到端验收结果见 `docs/validation.md`。

## 规划参数

创建项目时可按实际数据完整度逐步填写：

- 基础信息：项目名称、商品品类、目标市场、目标用户
- 定价目标：最低/最高售价、目标毛利率
- 财务参数：单位采购成本、单位物流成本、平台费率、税费率、营销费率、固定投入、预计销量
- 供应参数：供应商名称、MOQ、预计交期、最长可接受交期

系统以售价区间中位数作为当前测算售价，也支持审批修订时直接指定计划售价。缺少关键数据时不会伪造结论，财务和评分结果会明确返回待补字段、阻断项和风险提示。

## 运行与审批规则

- 同一项目只允许存在一个排队中、执行中或待审批的运行，避免重复任务覆盖结果。
- WebSocket 事件用于实时体验；事件发布异常不会导致已完成的 Agent 主流程失败。
- 前端会用 PostgreSQL 运行快照恢复流程图，Redis 事件过期后仍可查看最终状态。
- 审批仅允许处理仍处于待审批状态的运行；通过后完成，驳回后取消，要求修订后按新参数重新执行。
- 待审批任务支持审批人在线领取和释放；普通审批人不能处理他人已领取的任务，管理员可释放占用或代为处理，避免多人同时审批同一方案。
- 审批任务默认设置 24 小时处理时效，可通过 `APPROVAL_SLA_HOURS` 调整；审批中心标记即将到期和已超时任务，管理员可按账号将任务转派给指定审批人。
- 进行中或待审批的项目不能修改参数；终态项目修改后自动回到草稿状态。
- 每次运行保留独立输入和结果快照，可在工作台运行历史中回看。

## 身份、租户与权限

- 当前 `AUTH_MODE=local` 用于本地和 Docker 开发；可通过 `LOCAL_AUTH_USER_ID`、`LOCAL_AUTH_TENANT_ID` 和 `LOCAL_AUTH_ROLES` 配置默认身份，默认值为 `local-user`、`default` 租户和 `admin` 角色。页面顶部提供“切换本地身份”，可在 `admin`、`planner`、`approver`、`viewer` 预设档案间切换，便于验收不同权限入口；也可通过 `LOCAL_AUTH_PROFILES` 调整可选档案。
- `OBJECT_STORAGE_PROVIDER=local` 用于本地 Docker 文件卷；未来接入阿里云 OSS 时保持业务层的对象键不变，只替换对象存储适配器。
- REST 请求统一通过 `Authorization: Bearer <token>` 传递身份，前端 Axios 封装自动附加本地保存的访问令牌。
- WebSocket 建连前同样完成身份认证，并先校验运行所属租户，未授权连接不能订阅其他租户的实时事件。
- `viewer` 可读取本租户业务数据；`planner` 可创建和修改项目、启动运行、导入数据及生成报告；`approver` 可执行线上审批；`admin` 拥有全部权限并可查看审计台账。
- 项目、运行、证据、审批、分析、报告和审计接口都以认证身份中的 `tenant_id` 作为服务端过滤条件，不接受客户端自行指定租户。
- 后续接入企业 OIDC/SSO 时只替换 `IdentityProvider`，业务路由继续使用同一身份与角色依赖。

## 审计与健康状态

- 管理员可通过 `GET /api/v1/audit-events` 按项目、实体类型和动作过滤审计事件。
- 审计事件记录操作人、实体、动作、业务详情和发生时间，当前写入 PostgreSQL。
- `GET /health/ready` 实时探测 PostgreSQL、Redis、Milvus、Embedding 和 Reranker。
- PostgreSQL、Redis 和 Milvus 决定核心就绪状态；模型服务未启动时显示不可用，但研究 Agent 仍可按降级策略进入审批。

## 分析与报告

- `GET /api/v1/analytics/dashboard` 返回驾驶舱所需的全量统计和少量最新业务记录，首页不再轮询项目、审批、选品和立项全表。
- `GET /api/v1/analytics/notifications` 按当前角色返回可处理审批、异常项目、选品、导入和索引提醒汇总，通知中心无需全量扫描业务表。
- `GET /api/v1/analytics/opportunities/page` 分页返回项目最新运行的机会分、证据数、毛利率和供应风险；机会图表默认只读取最近 12 个项目。
- 数据质量汇总返回 `problem_import_total` 和最多 10 个代表性异常批次，异常数据增长时仍保持首页响应稳定。
- `GET /api/v1/data-imports/coverage` 使用 PostgreSQL 聚合覆盖率和主要业务维度，不在 API 进程内扫描全部证据。
- `GET /api/v1/data-imports/duplicates/page` 分页返回重复候选组，`GET /api/v1/data-imports/duplicates/group` 按页读取组内记录；审核结果会在候选集合变化时自动失效并重新进入待处理。
- 审计项目和批次版本选择器使用服务端远程搜索，保留当前选项的同时限制单次返回数量。
- `POST /api/v1/planning-projects/{project_id}/runs/{run_id}/reports` 创建异步 XLSX 报告任务。
- `GET /api/v1/planning-reports/{report_id}` 查询生成状态，完成后通过下载接口获取文件。
- 报告生成使用 pandas + openpyxl，并由 Celery `report.generate` 队列执行。

## 数据职责

- PostgreSQL：项目、运行结果、财务结果、审批和审计等权威业务数据
- Redis：Celery、Agent Checkpoint、共享状态和 WebSocket 事件
- Milvus：评论、商品、供应商和规划文档向量索引
- 本地 Docker Volume：开发阶段文件存储，后续替换为阿里云 OSS Adapter

## 阿里云预留

当前不接入实际云服务，但已按 Port/Adapter 结构预留：

- `ObjectStorageProvider`：后续实现阿里云 OSS
- `IdentityProvider`：后续实现企业 OIDC/SSO
- `ExternalApprovalProvider`：后续实现钉钉或公司 OA
- `TelemetryProvider`：后续实现阿里云日志与应用监控
