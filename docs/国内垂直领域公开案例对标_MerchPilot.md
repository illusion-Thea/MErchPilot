## 二、补充案例

### 2.1 韩都衣舍：AI+BI智能商品决策系统

| 项目 | 内容 |
| --- | --- |
| 垂直领域 | 服装零售 / 商品企划 / 柔性供应链 |
| 案例企业 | 韩都衣舍、知衣科技 |
| 公开链接 | [知衣科技官方案例](https://www.zhiyitech.cn/activity/all/62) |
| 业务痛点 | 服装趋势变化快、款式数量大，款式研发和评审依赖人工经验；企业需要同时参考市场大盘、企业销售和款式图片；多人线下选款、订货及反馈流程效率较低。 |
| 解决方案 | 建设AI+BI智能商品决策系统，对款式图片和业务数据进行结构化、标签化处理；根据企业条件进行款式推荐，实时对比市场和企业数据；支持线上预审、移动端反馈、PC端评审与人员管理，并对单款销售情况进行数据化复盘。 |
| 公开效果 | 官方案例披露，年度库存周转率达到6次以上，当季售罄率达到90%—95%，选款效率提升30%；产品上新15天后按照“爆、旺、平、滞”分类并制定运营策略。 |
| 与MerchPilot的对应关系 | 对应商品数据治理、商品机会评分、概念方案、线上人工审批、正式选品、单品复盘和业务人员参与决策。该案例尤其适合说明为什么系统需要“人在环”，而不是让Agent自动决定最终商品。 |

## 四、可直接填写版本

### 垂直领域

实体零售 / 商品企划 / 智能选品

### 案例

多点Dmall——基于大模型驱动的多Agent技术，实现实体零售精准选品、智能补货与动态出清。

### 材料

`docs/国内垂直领域公开案例对标_MerchPilot.md`

### 链接

[北京市经济和信息化局公开案例](https://jxj.beijing.gov.cn/ztzl/ywzt/hbjhsy/alzs/index_6.html)

### 业务痛点

实体零售商品数量大、生鲜保质期短，商品选品、补货、定价与出清高度依赖人工经验。消费者需求、销售、库存、促销、价格和损耗数据分散，传统固定规则难以适应不同门店、商圈和商品生命周期，容易造成缺货、滞销、促销成本过高和商品损耗。

### 解决方案

通过大模型驱动的多Agent系统融合零售数据和行业知识，实现商品精准选品、智能补货、动态折扣和临期出清。不同Agent分别处理需求分析、商品判断、库存预测、补货建议和价格策略，并将决策结果传递给实际业务流程。公开案例显示，AI智能出清使商品正价销售率提升10%、促销费用减少15%；AI智能补货将生鲜损耗率控制在3%，商品有货率达到98%。

### 项目职责

参考多点Dmall、韩都衣舍和绝味食品等国内公开案例，负责MerchPilot证据驱动的商品规划与智能选品核心链路。完成PostgreSQL与Milvus协同的业务事实和RAG证据检索体系；使用LangGraph编排市场研究、竞品分析、用户洞察、商品概念、供应评估、财务测算和机会评分Agent；设计Prompt、Agent工具及Pydantic结构化输出；使用Celery、Redis Checkpoint、重试和分布式锁保障长任务可靠执行；建设系统内人工审批、方案修订与版本恢复流程，并配合React前端实时展示Agent进度和审批状态。

## 七、最终推荐结论

### 7.1 只提交一个案例

如果允许填写平台型案例，优先选择 **天猫新品创新中心TMIC**。其官方资料明确披露千问、淘宝商品知识库、本地知识库和定制AI Agent，并直接服务新品研发，与MerchPilot的“RAG证据+Agent商品企划”结构最接近。

如果必须填写单一零售企业落地案例，优先选择 **多点Dmall**。它具备政府来源、明确的多Agent描述、精准选品业务和量化经营指标，真实性最容易核验。

### 7.2 面试重点是商品企划

选择 **韩都衣舍**。它能够自然引出数据治理、趋势图片标签、智能款式推荐、线上预审、人工评审、试销分类和快速返单，与MerchPilot从数据到人工审批、正式选品和复盘的业务链路最接近。

### 7.3 面试重点是技术架构

组合使用三个案例：

1. 用多点Dmall说明零售Multi-Agent和商品决策。
2. 用什么值得买“小值”说明RAG、商品库和内容库。
3. 用绝味食品说明多个Agent分工、企业知识库和业务工具执行。

### 7.4 推荐的项目背景表述

> 项目前期调研了多点Dmall的零售多Agent商品决策、值得买科技的消费RAG和商品知识库、绝味食品的多Agent协作，以及韩都衣舍的智能商品企划与人工评审流程。在此基础上，我重点负责MerchPilot的RAG证据链、LangGraph Agent编排、Celery异步执行、Redis Checkpoint和人在环审批能力。

## 九、最值得深入研究的五个案例

### 9.1 天猫TMIC：最接近MerchPilot的知识库与Agent结构

TMIC已经明确使用千问、淘宝商品知识库、品牌本地知识库和定制AI Agent辅助新品研发。该案例可以对应MerchPilot的模型服务、企业RAG、私有业务数据、Agent编排和商品方案生成。差异是公开材料没有说明向量数据库、Checkpoint、异步任务和审批状态机。

### 9.2 京东七鲜：最接近完整商品开发流程

七鲜案例覆盖模糊需求、趋势洞察、用户评价、竞品分析、供应可行性、概念生成、包装设计、选品会评分、人员反复修改、上市和销售复盘，是目前业务过程与MerchPilot最相似的案例。由于详细技术信息主要来自采访报道，正式提交时应把“多智能体流程”与“七鲜官方已推出AI商品”分开注明来源。

### 9.3 多点Dmall：最可靠的零售多Agent案例

多点案例的优势是北京市经信局直接披露了多Agent、精准选品、动态折扣、补货和出清及量化效果，真实性强。其不足是偏向在售商品运营，没有公开新品概念生成和人工方案审批。

### 9.4 华凯易佰：最可靠的跨境电商AI选品案例

上市公司信息披露中明确出现自然语言选品、选品参考线、选品评分模型、AI采购Agent、企业知识库和供应商报价处理，适合对标MerchPilot的选品评分、供应评估、Agent工具调用和风控规则。

### 9.5 知小衣：最接近服装商品企划多Agent

知小衣公开了四个智能体共同完成趋势、选款、商品解读和设计的工作流，与MerchPilot的市场研究、竞品分析、用户洞察和概念生成节点高度相似。它更偏设计端，尚未公开财务测算、供应商评估和审批恢复机制。

### 12.1 严格要求下的推荐顺序

如果提交方要求链接正文必须同时包含项目、痛点和解决方案，推荐顺序为：

1. **三态股份**：商品研究、选品模型、人工确认、供应商、采购、库存与履约链路最完整。
2. **韩都衣舍**：页面直接按照背景、挑战、方案和效益组织，最方便审核人员阅读。
3. **知衣科技国家数据局案例**：政府来源明确写出服装行业痛点、解决方案和效果。
4. **绝味食品**：痛点、4个Agent、知识库、执行工具和实验效果均在同一页面，但业务偏会员营销。
5. **华凯易佰**：项目和解决方案详细，量化效果不足时应明确写“公开资料未披露”。

天猫TMIC和多点Dmall依然是真实且高匹配的案例，但其单个页面对“改造前痛点”的描述不够完整，适合作为技术或效果补充链接，不建议独立承担全部真实性证明。
